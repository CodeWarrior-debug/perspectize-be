## Known Gaps / Deferred to v1.1

1. **Phase 4 (Add Perspective Flow)** — Modal UI redesigned, but form implementation deferred
   - Impact: Users cannot yet create perspectives, but infrastructure (GraphQL types, backend) is ready
   - v1.1 scope: Complete form, integrate with dataloaders (Phase 4.1), test coverage

2. **Phase 6 (Error Handling)** — Patterns established (Phase 7+), but comprehensive audit not run
   - Impact: Silent failures mostly eliminated, but C-06/C-08 JSON unmarshal errors still possible
   - v1.1 scope: Comprehensive error audit, standardize not-found handling

3. **Phase 8.1 (API & Schema Quality)** — Deferred post-Phase-9
   - Impact: Schema uses `String` instead of `DateTime`/`ContentType` enum, nested resolvers not optimized
   - v1.1 scope: DateTime scalar, nested field resolvers, input validation

4. **Phase 10 (Frontend Quality & Test Coverage)** — Deferred post-Phase-9
   - Impact: graphql-codegen not set up, dead code detection not run
   - v1.1 scope: Codegen setup, error boundaries, dead code cleanup via Knip

## Decisions Made During v1.0

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| SvelteKit static adapter | Enables cheap GitHub Pages hosting, all data via GraphQL client-side | ✅ Successful — deployed on Sevalla Static Sites |
| TanStack Query over manual fetch | Official Svelte support, built-in caching, error handling | ✅ Successful — replaced by Phase 7.3, now core pattern |
| AG Grid over TanStack Table | Feature richness for sorting/filtering/pagination | ✅ Successful — handles 50K+ items with server-side ops |
| Hex-clean GORM ORM | Preserve architecture while reducing boilerplate 35% | ✅ Successful — domain models stay pure, tests unchanged |
| Cursor-based pagination | Database-efficient, offset-agnostic sorting | ✅ Successful — fixed by Phase 7.2 (gorm-cursor-paginator) |
| JWT + httpOnly cookies | Stateless auth, CORS-friendly, simple refresh | ✅ Successful — deployed Phase 9, no CSRF issues |
| User dropdown selector (no auth) | Simpler v1.0, Clerk auth planned for v1.1 | ⚠️ Ready for migration — auth infrastructure in place (Phase 9) |

## Final Remarks

**v1.0 has shipped a complete, production-ready frontend** with:
- Full Activity page with server-side ops (sort/filter/pagination)
- Add Video flow with duplicate detection
- User selector with session persistence
- Mobile-responsive design (375px–4K)
- Production-grade security (JWT auth, rate limiting, CORS, CSP)
- ~80% test coverage with continuous monitoring

**Perspective creation (Phase 4)** is the primary deferred feature, but the modal UI redesign (#215) is merged and form implementation can proceed in v1.1 without rework.

**Post-MVP concerns remediation (Phases 7–9)** added architecture cleanup, caching fixes, and security hardening, bringing the codebase to a sustainable long-term foundation.
