## Overview

Perspectize v1.0 is a complete SvelteKit frontend for discovering YouTube videos, adding new videos via URL paste, and viewing content in an interactive AG Grid table. Built with TanStack Query, shadcn-svelte components, and Tailwind CSS v4. Includes backend architecture cleanup (GORM ORM migration, cursor pagination), caching remediation, performance monitoring infrastructure, and comprehensive security hardening (JWT auth, authorization directives, CORS, rate limiting).

The milestone spans:
- **v1.0 MVP** (Phases 1–5): Core frontend + data layer + deployment (shipped 2026-02-16)
- **Post-MVP Concerns** (Phases 6–10): Architecture cleanup, security, quality (Phases 7–9 executed by 2026-03-03)
- **Parallel Work** (Phase 17): URL normalization + duplicate upsert (shipped 2026-02-22)

## Milestone Summary

### Execution Timeline
- **Phase 1–3.2:** Frontend MVP (2026-02-05 → 2026-02-16, ~11 days)
- **Phase 5, 7–9:** Post-MVP concerns (2026-02-13 → 2026-03-03, ~19 days)
- **Phase 17:** Parallel URL normalization (2026-02-22, within Phase 7 window)
- **Formal v1.0 closure:** 2026-09-04 (6+ months after initial delivery, incorporating parallel work stream)

### Key Decisions
- **Stack**: SvelteKit + TanStack Query + AG Grid + shadcn-svelte + Tailwind CSS v4 (all chosen for design system alignment)
- **Architecture**: Hex-clean with GORM ORM (domain models pure, DB models in adapter layer)
- **Deployment**: Sevalla for both static frontend and GraphQL backend (inexpensive shared hosting)
- **Auth approach**: JWT + httpOnly cookies (stateless, CORS-friendly, simple refresh strategy)
- **Pagination**: Cursor-based with compound keyset encoding (database-efficient, offset-agnostic sorting)
- **Error handling**: Unified sanitization patterns (no PII/secrets in logs or GraphQL responses)

### Issues Resolved
- **C-02**: Cursor pagination broken for non-ID sorts → Fixed by Phase 7.2 (gorm-cursor-paginator)
- **H-01, H-02**: Adapter-to-adapter coupling → Fixed by Phase 7 (service port interfaces + DI)
- **C-06, C-07, C-08**: Silent failures in unmarshal/parse → Fixed by Phase 6+ and 7.4 (logging + error handling)
- **H-13**: Sensitive data in GraphQL errors → Fixed by Phase 9-05 (YouTube API key sanitization)
- **P0 caching**: ActivityTable bypassing TanStack Query → Fixed by Phase 7.3 (query migration)
- **P0 security**: Eruda in production → Removed by Phase 7.3-01

### Technical Debt Incurred
- **Phase 4 deferred**: Add Perspective Flow form (business logic ready, UI needs finalization)
- **Phase 6 partial**: Error handling patterns established but comprehensive audit deferred
- **Phase 8.1 deferred**: Schema quality improvements (nested resolvers, DateTime scalars) planned for Phase 8.1
- **Phase 10 deferred**: Frontend quality & test coverage (graphql-codegen setup, error boundaries, dead code cleanup)

### Lessons Learned
1. **Decimal phase insertion works well** for urgent fixes without disrupting numbering (2.1, 3.1, 3.2, 7.1-7.4 all successfully inserted)
2. **Architecture cleanup (Phase 7)** is easier when approached incrementally (ORM migration → pagination → caching → monitoring)
3. **Security hardening (Phase 9)** should include both implementation (auth) and documentation (secrets rotation)
4. **Post-MVP concerns remediation** typically requires 50% of MVP execution time (MVP 11 days, concerns 19 days)
5. **Parallel work streams** (Phase 17) require cross-phase dependency tracking but can execute alongside main phases
