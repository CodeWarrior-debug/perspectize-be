**M-04: Popovers become dialogs at <768px**

The FormPopover component currently always renders a Popover. Modify it to detect viewport width and render a Dialog at <768px instead.

Approach: Use `$state` + `$effect` with `matchMedia` to track mobile state, then conditionally render either Popover or Dialog.

1. Add mobile detection:
```typescript
let isMobile = $state(false);

$effect(() => {
  if (typeof window === 'undefined') return;
  const mq = window.matchMedia('(max-width: 767px)');
  const handler = (e: MediaQueryListEvent | MediaQueryList) => {
    isMobile = 'matches' in e ? e.matches : (e as MediaQueryListEvent).matches;
  };
  handler(mq);
  mq.addEventListener('change', handler);
  return () => mq.removeEventListener('change', handler);
});
```

2. Import Dialog components (already available in shadcn):
```typescript
import { Dialog, DialogContent, DialogHeader, DialogTitle, DialogDescription, DialogFooter } from '$lib/components/shadcn';
```

3. In the template, use `{#if isMobile}` to switch between Dialog and Popover:

**Mobile (Dialog) branch:**
```svelte
{#if isMobile}
  <Button
    variant={triggerVariant}
    size={triggerSize}
    onclick={() => (open = true)}
  >
    {@render triggerIcon()}
    <span class="hidden sm:inline">{triggerLabel}</span>
  </Button>
  <Dialog bind:open>
    <DialogContent class="sm:max-w-md">
      <DialogHeader>
        <DialogTitle>{title}</DialogTitle>
        <DialogDescription>{description}</DialogDescription>
      </DialogHeader>
      <form onsubmit={handleSubmit}>
        {@render formFields()}
        <div class="flex gap-2 justify-end mt-4">
          <Button type="button" variant="outline" onclick={() => (open = false)} disabled={isPending}>
            Cancel
          </Button>
          <Button type="submit" disabled={isPending || isSubmitDisabled}>
            {isPending ? pendingLabel : submitLabel}
          </Button>
        </div>
      </form>
    </DialogContent>
  </Dialog>
{:else}
  <!-- Existing Popover code (unchanged) -->
  <Popover bind:open>
    <PopoverTrigger class={buttonVariants({ variant: triggerVariant, size: triggerSize })}>
      {@render triggerIcon()}
      <span class="hidden sm:inline">{triggerLabel}</span>
    </PopoverTrigger>
    <PopoverContent {align} sideOffset={8}>
      <form onsubmit={handleSubmit}>
        ...existing popover form content...
      </form>
    </PopoverContent>
  </Popover>
{/if}
```

Note: The `<span class="hidden sm:inline">{triggerLabel}</span>` pattern from Plan 07 should already be in place. If not, include it here too.

```svelte
<Select value={currentUserId ? String(currentUserId) : ''} onValueChange={(v) => {
  setSelectedUserId(v ? parseInt(v, 10) : null);
}}>
  <SelectTrigger class="h-9 w-[180px]">
    {#if usersQuery.isLoading}
      Loading users...
    {:else if currentUserId && usersQuery.data}
      {usersQuery.data.users.find(u => u.id === String(currentUserId))?.username ?? 'Select user...'}
    {:else}
      Select user...
    {/if}
  </SelectTrigger>
  <SelectContent>
    {#if usersQuery.data}
      {#each usersQuery.data.users as user}
        <SelectItem value={user.id}>{user.username}</SelectItem>
      {/each}
    {/if}
  </SelectContent>
</Select>
```

Note: Check bits-ui docs for exact Select API. bits-ui 2.x uses Svelte 5 patterns. The Select.Root may use `selected` instead of `value` - check the installed bits-ui version's API.

- Shows currently selected user
- Triggers setSelectedUserId on change
- Shows "Select user..." placeholder when none selected
- Shows "Loading users..." when loading
- Shows error state when query fails
