# Phase 03.5.1: Wikidata Category Attribution - Context

**Gathered:** 2026-02-28
**Status:** Ready for planning
**Source:** Conversation-based design discussion

<domain>
## Phase Boundary

Build a Wikidata-backed category system for content items. Users manually search Wikidata entities via a typeahead in the AG Grid ActivityTable, select one as the content's primary category. Categories are cached locally in a dedicated table. No auto-extraction, no hierarchical taxonomy, no seed data.

This phase delivers: Wikidata Go HTTP client, categories database table, primary_category_id FK on content, wikidataSearch GraphQL query, AG Grid category column with typeahead popover.

</domain>

<decisions>
## Implementation Decisions

### Wikidata Client
- Entity Search API only (`wbsearchentities`) — no SPARQL, no full entity fetch (REST /entity/{QID})
- Go HTTP client wrapping `https://www.wikidata.org/w/api.php?action=wbsearchentities`
- Returns: Q-ID, label, description, entity type
- English only initially (language=en)
- Timeout + retry with exponential backoff
- Mandatory User-Agent header per Wikidata policy

### Category Domain Model
- Domain concept named "Category" — Wikidata-backed grouping
- Light data per category: Q-ID (wikidata_qid), label, description, entity_type
- Dedicated `categories` table — shared/deduplicated across content items
- Categories table doubles as cache: upsert when user selects a Wikidata result
- No ltree hierarchy — flat categories only
- No Google NL taxonomy, no seed data
- Primary category only for now — secondaries deferred to a later phase

### Database Schema
- `categories` table: id (PK), wikidata_qid (unique), label, description, entity_type, created_at, updated_at
- `primary_category_id` FK on existing `content` table → `categories.id` (nullable, no content has categories yet)
- Migration number: 000014 (next available after 000013_add_perspective_refs_claims)
- No junction table needed — just a single FK for primary category

### GraphQL API
- Single query: `wikidataSearch(query: String!, language: String, limit: Int): [WikidataSearchResult!]!`
- WikidataSearchResult type: qid, label, description, entityType
- Thin proxy — backend calls Wikidata API, returns results
- No category CRUD mutations needed — categories are created implicitly on selection
- Content type gains `primaryCategory: Category` field (nullable)
- Category type: id, wikidataQid, label, description, entityType, createdAt

### Content Flow & AG Grid UX
- Category appears as a column in the ActivityTable AG Grid
- Single column for primary category
- Empty cells clickable to add a category
- Click opens a typeahead popover with live Wikidata search
- User types >= 2-3 chars, frontend calls wikidataSearch query, shows top results
- User selects result → backend upserts into categories table → assigns as content's primary category
- Primary category changeable by clicking existing value and picking a new one

### Frontend
- Full frontend implementation included in this phase
- Typeahead search component (debounced, calls wikidataSearch GraphQL query)
- AG Grid cell renderer for category column (shows label, clickable)
- AG Grid cell editor or popover for category selection
- TanStack Query integration for search results

### Claude's Discretion
- Exact HTTP client implementation details (retries, timeouts, connection pooling)
- Error handling strategy for Wikidata API failures (show error in popover vs silent fail)
- Debounce timing for typeahead (suggest 300-500ms)
- AG Grid column placement and responsive tier
- GraphQL resolver wiring and service layer structure
- Whether to add category-based sorting/filtering (optional, nice-to-have)
- GORM model structure and mapper implementation details

</decisions>

<specifics>
## Specific Ideas

- Wikidata Entity Search endpoint: `https://www.wikidata.org/w/api.php?action=wbsearchentities&search={query}&language=en&format=json&limit=10`
- Categories table acts as local cache — when user selects "Kansas City Chiefs (Q223522)", upsert into categories then set content.primary_category_id
- Follow existing hexagonal architecture: domain model → port interface → service → GORM adapter → GraphQL resolver
- Follow existing patterns: ContentRepository for CategoryRepository, ContentModel for CategoryModel, etc.
- AG Grid column should follow the responsive tier pattern in ActivityTable.svelte
- Frontend search uses TanStack Query with keepPreviousData for smooth typeahead UX

</specifics>

<deferred>
## Deferred Ideas

- Secondary categories (many-to-many junction table) — future phase
- Wikidata REST API for full entity details — not needed for category selection
- Wikidata SPARQL queries for complex entity relationships — not needed
- Auto-extraction of categories from video metadata (title, tags, description)
- Category hierarchy / ltree paths — flat categories only in this phase
- Google NL taxonomy integration — replaced by direct Wikidata search
- Seed categories — users create categories organically via Wikidata search
- Multi-language support (language parameter exists but hardcoded to English)
- Category-based content filtering and sorting in AG Grid

</deferred>
