  <action>
    1. **Update `gqlgen.yml`** — add field resolver directives under `models:` section:
       ```yaml
       Perspective:
         fields:
           user:
             resolver: true
           content:
             resolver: true
       Content:
         fields:
           addedBy:
             resolver: true
       ```
       Add these AFTER the existing model bindings (SortOrder, ContentSortBy, etc.), still inside the `models:` block.

    2. **Regenerate gqlgen code:** Run `cd backend && make graphql-gen`
       - This creates `perspective.resolvers.go` and `content.resolvers.go` with stub methods
       - The generated stubs will have `panic("not implemented")` — replace them next
       - Note: `generated.go` will be regenerated (large file, expected)

    3. **Implement `perspectiveResolver.User()` in `perspective.resolvers.go`:**
       - `obj *model.Perspective` has `UserID string` (GraphQL ID scalar → Go string)
       - Convert: `userID, err := strconv.Atoi(obj.UserID)` — handle error
       - Call: `domainUser, err := loaders.GetUser(ctx, userID)`
       - Handle `dataloadgen.ErrNotFound` → return `nil, nil` (user deleted gracefully)
       - Convert: `return userDomainToModel(domainUser), nil`
       - Import `loaders` package: `"github.com/CodeWarrior-debug/perspectize/backend/internal/adapters/graphql/loaders"`

    4. **Implement `perspectiveResolver.Content()` in `perspective.resolvers.go`:**
       - `obj.ContentID` is `*string` (optional relationship)
       - Guard: `if obj.ContentID == nil { return nil, nil }` — no content associated
       - Convert: `contentID, err := strconv.Atoi(*obj.ContentID)`
       - Call: `domainContent, err := loaders.GetContent(ctx, contentID)`
       - Handle `dataloadgen.ErrNotFound` → return `nil, nil`
       - Convert: `return domainToModel(domainContent), nil`

    5. **Implement `contentResolver.AddedBy()` in `content.resolvers.go`:**
       - `obj *model.Content` has `AddedByUserID string`
       - Convert: `userID, err := strconv.Atoi(obj.AddedByUserID)`
       - Call: `domainUser, err := loaders.GetUser(ctx, userID)`
       - Handle `dataloadgen.ErrNotFound` → return `nil, nil`
       - Convert: `return userDomainToModel(domainUser), nil`

    6. **Important:** The helper functions `userDomainToModel` and `domainToModel` are in `helpers.go` within the same `resolvers` package — they are directly accessible. Do NOT duplicate them.

    7. **Important:** Import `errors` package for `errors.Is(err, dataloadgen.ErrNotFound)` check. Import `"github.com/vikstrous/dataloadgen"` for the `ErrNotFound` sentinel.

    8. Run `cd backend && go build ./...` to verify compilation.
  </action>

<task type="auto">
  <name>Task 2: Wire middleware in main.go and add integration tests for N+1 prevention</name>
  <files>
    backend/cmd/server/main.go
    backend/test/resolvers/content_resolver_test.go
  </files>
  <action>
    1. **Wire middleware in `main.go`:**
       - Import: `"github.com/CodeWarrior-debug/perspectize/backend/internal/adapters/graphql/loaders"`
       - Add `r.Use(loaders.Middleware(userRepo, contentRepo))` AFTER the CORS middleware and BEFORE `r.Handle("/graphql", srv)`
       - Pass the raw repository instances (`userRepo`, `contentRepo`), not the services — dataloaders bypass the service layer
       - Note: `userRepo` and `contentRepo` are already declared as variables in main.go (lines 101-102)

    2. **Add `setupTestServerWithLoaders` helper in `content_resolver_test.go`:**
       - Accepts `*mockContentRepository`, `*mockYouTubeClient`, `*mockUserRepository`, `*mockPerspectiveRepository`
       - Creates services and resolver (same as existing `setupTestServer`)
       - Creates gqlgen handler
       - Wraps handler with `loaders.Middleware(userRepo, contentRepo)` BEFORE creating httptest.Server
       - This ensures field resolvers can find loaders in context during tests

    3. **Add integration test: `TestPerspectiveNestedUser_ResolvesCorrectly`:**
       - Set up `mockPerspectiveRepository.listFn` to return 3 perspectives with UserID=1,2,3
       - Set up `mockUserRepository.getByIDsFn` to return users with matching IDs
       - Execute: `{ perspectives { items { id userID user { id username } } } }`
       - Assert: Response has no errors
       - Assert: Each perspective's `user.id` matches `userID`
       - Assert: `user.username` is populated (not null)

    4. **Add integration test: `TestPerspectiveNestedContent_ResolvesCorrectly`:**
       - Set up perspectives with ContentID=10,20 (one with nil ContentID)
       - Set up `mockContentRepository.getByIDsFn` to return content with matching IDs
       - Execute: `{ perspectives { items { id contentID content { id name } } } }`
       - Assert: Perspectives with contentID get populated content objects
       - Assert: Perspective with nil contentID has `content: null`

    5. **Add integration test: `TestContentNestedAddedBy_ResolvesCorrectly`:**
       - Set up content list with AddedByUserID=5
       - Set up `mockUserRepository.getByIDsFn` to return user with ID=5
       - Execute: `{ contents { items { id addedByUserID addedBy { id username } } } }`
       - Assert: `addedBy.id` matches `addedByUserID`

    6. **Add integration test: `TestNestedQueries_BatchIntoSingleGetByIDs`:**
       - **Key N+1 prevention test**
       - Set up `mockPerspectiveRepository.listFn` to return 5 perspectives with varying UserIDs
       - Add **call counter** (`callCount int`) to `mockUserRepository.getByIDsFn` (increment each call)
       - Execute: `{ perspectives { items { user { username } } } }`
       - Assert: `getByIDsFn` called exactly **1 time** (not 5 times)
       - This proves batching works — 5 individual Load() calls are batched into 1 GetByIDs call

    7. Run `cd backend && go test ./...` to verify all tests pass.
